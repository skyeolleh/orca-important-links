# 중요 링크 — Orca 플러그인

**0.4.2**는 Orca 우측 패널에서 실제 **현재 Codex 세션 / 글로벌** 링크를 나눠 관리합니다.

- 선택한 Codex 세션의 답변에 포함된 Markdown 링크를 자동 수집합니다. 프리뷰를 먼저 표시합니다.
- 탭·분할 터미널·작업 공간을 바꾸면 실제 Codex 세션 ID에 맞춰 목록도 바뀝니다. 새 세션에 이전 세션의 링크를 붙이지 않습니다.
- 별표나 글로벌의 `+`로 등록한 링크는 다른 세션에서도 보이며 Orca 재시작 후 유지됩니다.
- 카드를 누르면 웹 주소나 로컬 프리뷰·문서·미디어가 기본 앱으로 열립니다.
- 각 영역의 추가·삭제는 독립적입니다. 삭제 직후 되돌리기도 지원합니다.

**플러그인 0.4.x 설치와 Orca 연결 코드 적용이 모두 필요합니다.** 현재 Orca의 공개 플러그인 패널 API에는 실제 활성 세션, 대화 기록 구독, 영구 저장 및 직접 열기 기능이 없습니다. 이 저장소의 연결 코드가 그 부분을 Orca 앱에 추가합니다. 연결 없이 자동 수집됐다고 표시하지 않으며 패널에 연결 대기 안내가 나옵니다.

0.4.2는 연결 코드를 실행 중인 앱에도 설치할 수 있도록 기존 ASAR 파일 위치와 캐시 읽기를 보존합니다. 새 시작 코드를 파일 뒤에 추가하고 그 항목의 헤더와 SHA256 무결성 정보만 바꿉니다. 실행 파일 보안 설정과 다른 파일의 내용·위치 정보는 바꾸지 않습니다. 이미 설치한 플러그인 0.4.0/0.4.1도 호환됩니다. 패널만 재설치해서는 연결 코드가 설치되지 않습니다.

## 플러그인 설치와 업데이트

버전을 지정한 직접 설치 주소:

```text
https://github.com/skyeolleh/orca-important-links.git#0.4.2
```

Orca **설정 → 플러그인 → 플러그인 설치 → Git 저장소**에서 입력하고 검토·활성화합니다. `0.4.2`는 실제 Git 태그입니다. 이전 태그도 유지합니다.

메뉴에서 업데이트하려면 **설정 → 플러그인 → 소스 관리**에 다음 값을 등록하고 **All** 목록에서 설치하세요.

| 항목 | 값 |
| --- | --- |
| Git URL | `https://github.com/skyeolleh/orca-important-links.git` |
| Git ref | `main` |

다음 버전은 **새로고침 → All → 업데이트 확인**으로 적용합니다. Git 직접 설치는 마켓플레이스 업데이트 버튼 대상이 아닙니다. 기존 로컬 설치와 겹쳐 설치 버튼이 보이지 않으면, 필요한 수동 목록을 백업한 뒤 기존 설치를 제거하고 마켓플레이스에서 설치하세요. 업데이트 후 재검토·활성화가 필요할 수 있습니다.

## Orca 연결 코드 적용 — Windows 1.4.222

현재 연결 코드는 **Windows Orca 1.4.222** 설치본만 지원합니다. 저장소를 받은 폴더에서 Node 22 이상으로 준비합니다. 외부 패키지 설치는 필요 없습니다.

```powershell
node host/prepare-connector.mjs
powershell -NoProfile -File host/Apply-Connector.ps1 -AllowRunning -ValidateOnly
```

이 단계는 설치본을 변경하지 않습니다. 설치본의 버전, 상태 저장소 진입점과 실행 파일의 보안 설정을 확인하고 원본 백업·연결 파일·적용 계획을 `host/artifacts/`에 만듭니다. 원래 ASAR 데이터 시작점과 모든 기존 파일의 캐시 읽기를 검증합니다. 기존 헤더 공간에 새 메타데이터가 들어가지 않으면 중단합니다. ASAR 서명 검사가 켜져 있으면 중단하며 보안 설정을 바꾸지 않습니다.

검증된 파일 위치 보존 계획은 Orca가 실행 중이어도 적용할 수 있습니다.

```powershell
powershell -NoProfile -File host/Apply-Connector.ps1 -AllowRunning
```

`-AllowRunning`은 원본·연결 파일의 모든 기존 위치를 다시 검사하고 새 코드가 완전히 기록된 뒤 헤더를 갱신합니다. 기존 파일을 삭제하거나 바꿔치기하지 않습니다. 적용 전후 해시와 백업을 확인하며 다른 프로세스가 설치본을 바꿨으면 중단합니다. **적용 기록에 연결 적용 완료가 나온 다음 Orca를 한 번 재실행해야 연결 코드가 로드됩니다.** 종료 대기 설치와 달리 재실행 전에 설치가 끝났는지 확인할 수 있습니다. 상태 기록은 `host/artifacts/apply-status.txt`입니다.

Orca의 실제 ASAR 읽기 엔진으로 기존 캐시와 새 프로세스의 읽기를 창 없이 검사하려면 `node host/probe-stable-runtime.mjs`를 실행할 수 있습니다. 검증은 백업과 연결 파일의 임시 복사본만 변경하며 설치본은 변경하지 않습니다.

종료한 상태에서 적용하려면 `-AllowRunning` 없이 실행해도 됩니다. 기존 종료 대기 방식은 `-WaitForExit`로 남겨 두며 충돌 보고 보조 프로세스는 기다리지 않습니다. 앱이나 터미널을 강제로 종료하지 않습니다.

원상 복원은 Orca를 종료하고 다음 명령으로 진행합니다. 저장된 링크 자료는 지우지 않습니다.

```powershell
powershell -NoProfile -File host/Apply-Connector.ps1 -Restore
```

플러그인 업데이트는 연결 코드까지 자동으로 설치하지 않습니다. Orca 앱 자동 업데이트로 연결 파일이 교체될 수 있습니다. 다른 앱 버전이면 덮어쓰지 않으며 해당 버전에 맞는 연결 검증이 필요합니다. 이미 연결된 설치본을 다시 준비하려면 먼저 위의 복원 명령을 실행하세요.

## 작동 확인

1. 플러그인 **중요 링크 0.4.x**를 검토·활성화하고 우측 패널을 엽니다. 연결 대기 안내가 없어야 합니다.
2. Codex 세션 A에서 프리뷰 링크가 포함된 답변을 받습니다. 현재 세션에 자동으로 표시되는지 확인합니다.
3. 별표를 누르면 글로벌에도 나타납니다.
4. 새 Codex 세션 B를 선택하면 A의 현재 세션 링크는 표시되지 않고 글로벌 링크만 유지됩니다. 실제 세션 ID가 아직 생성되지 않은 새 터미널은 빈 목록으로 기다립니다.
5. A로 돌아가거나 Orca를 재시작하면 저장된 링크가 복원됩니다. 프리뷰 카드를 누르면 해당 파일이 기본 앱으로 열립니다.

## 저장과 수집 범위

자료는 Orca 렌더러의 로컬 저장소에 보관하며 현재 세션은 **실행 호스트 + 실제 Codex 세션 ID**, 글로벌은 공통 목록을 사용합니다. 같은 컴퓨터의 Orca 작업 공간·세션 간에 공유하며 다른 컴퓨터로 동기화하지 않습니다. 패널을 닫아도 플러그인이 활성화되어 있으면 선택한 세션의 수집은 계속됩니다.

새로 연결할 때 최근 최대 300개 메시지를 읽고 이후 답변을 구독합니다. 기존 수집 자료와 병합하며 세션당 최대 500개, 글로벌 최대 200개 링크를 보관합니다. 전체 과거 대화에서 모든 링크를 일괄 가져오는 기능은 아닙니다. 사용자 입력·도구 출력·하위 에이전트·코드 예제·이미지 삽입 문법의 주소는 자동 수집에서 제외합니다. 일반 텍스트 주소는 `+`로 직접 등록할 수 있습니다.

메뉴의 백업 내보내기는 **현재 세션과 글로벌**을 포함하며 다른 세션 목록까지 내보내지 않습니다. 백업 가져오기는 기존 자료를 유지하며 글로벌로 병합합니다. 이전 0.1/0.3 수동 작업 묶음도 글로벌로 가져옵니다. Orca 로컬 저장소 삭제에 대비해 필요한 링크를 백업하세요.

로컬 Codex 터미널과 구조화된 Codex 세션을 지원합니다. 원격 런타임 구독은 해당 실행 호스트로 보내지만 실제 원격 환경 검증은 남아 있습니다. 기존 SSH 터미널 기록 수집은 지원하지 않습니다. 원격 파일을 로컬 파일로 대신 읽거나 열지 않으며 원격 파일 바로 열기도 지원하지 않습니다.

연결 코드는 검토·활성화된 `yeojh-local.session-links` 0.4.x에만 동작합니다. 정확한 패널 창과 연결 토큰을 확인하고 등록된 링크만 열며 실행 파일은 열지 않습니다. 터미널에 명령을 주입하거나 수집한 대화·링크를 외부 서버로 보내지 않습니다.

## 개발과 검증

패널 소스는 `src/`, 앱 연결은 `host/`에 있습니다. 설치용 `panel.html`은 저장소에 포함되므로 플러그인 설치 시 빌드가 필요 없습니다.

```powershell
node build.mjs
node --test test/*.test.mjs
```

모델·구독·설치 구조 검사는 외부 의존성 없이 실행됩니다. 패널과 호스트 통합 검사는 이미 준비된 happy-dom 모듈 파일을 `HAPPY_DOM_MODULE` 환경 변수로 지정하면 실행되며, 없으면 그 검사만 건너뜁니다. 검사 실행이 패키지를 설치하거나 데스크톱 창을 조작하지 않습니다.

0.4.2 개발 환경에서 **29개 검사 통과, 건너뜀 0개**를 확인했습니다. 자동 수집, 실제 세션 분리, 글로벌 재시작 복원, 삭제·되돌리기, 늦은 구독 응답, 임의 요청 거부와 실제 배포용 묶음 코드의 패널 통신을 포함합니다. 설치본의 원래 캐시 5,123개 항목을 같은 위치에서 읽는 것을 확인했고 다른 5,122개 항목은 메타데이터도 유지합니다.

Windows Orca 1.4.222의 실제 파일 읽기 엔진을 화면 없이 실행해 교체 전 캐시가 원래 코드와 다른 파일을 읽고 새 프로세스가 새 연결 코드를 읽는 것을 확인했습니다. 2026-10-14 실제 설치본에 적용하고 최종 해시·새 프로세스의 연결 코드 읽기까지 확인했습니다. **앱 재실행 후 실제 패널 렌더·링크 자동 등록·파일 열기는 아직 수동 확인하지 않았습니다.**
